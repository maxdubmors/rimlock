## 1. Withheld host access

### Chrome

- **User controls.** Site access has three modes: "When you select the extension" (on click), "On [current site]" and "On all sites". Specific sites can also be added on the extension's details page ([CWS Help 2664769](https://support.google.com/chrome_webstore/answer/2664769)). In source these are `UserSiteAccess::{kOnClick,kOnSite,kOnAllSites}` ([CR/extensions/browser/permissions/site_permissions_helper.cc#L157-L183](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions/site_permissions_helper.cc#L157-L183)). Separately, a per-site user setting can block all extensions on an origin (`UserSiteSetting::kBlockAllExtensions` → `AddUserRestrictedSite`) or, behind a feature flag, grant all of them (`kGrantAllExtensions`) ([CR/extensions/browser/permissions_manager.cc#L338-L360](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions_manager.cc#L338-L360)).
- **Withholding mechanics.** Choosing On click or On site calls `SetWithholdHostPermissions(true)`. That calls `RemoveAllGrantedHostPermissions()`, which revokes everything `GetRevokablePermissions()` returns. That set is all currently granted host permissions; API permissions stay ([scripting_permissions_modifier.cc#L39-L58](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions/scripting_permissions_modifier.cc#L39-L58), [permissions_manager.cc#L791-L840](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions_manager.cc#L791-L840)). Choosing On all sites calls `GrantWithheldHostPermissions()`.
- **`permissions.contains({origins})`** checks only `active_permissions()` (explicit plus scriptable hosts). A withheld origin therefore returns `false` ([permissions_api.cc#L148-L192](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api.cc#L148-L192)).
- **`permissions.getAll()`** packs `active_permissions()`, so withheld hosts are absent ([permissions_api.cc#L194-L206](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api.cc#L194-L206)).
- **Events.** Withholding and granting go through `PermissionsUpdater` and then `PermissionsManager::NotifyExtensionPermissionsUpdated`. `PermissionsEventRouter` dispatches `permissions.onAdded` / `onRemoved` for `kAdded` / `kRemoved`, and dispatches nothing for `kPolicy` ([permissions_updater.cc#L664-L740](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions/permissions_updater.cc#L664-L740), [permissions_event_router.cc#L34-L67](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_event_router.cc#L34-L67)).
- **The user "block all extensions on this site" setting** is stored as a per-context `user_blocked_hosts` restriction (`PermissionsData::SetUserHostRestrictions`). It is not stored as a change to `active_permissions` ([permissions_data.cc#L265-L291](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/common/permissions/permissions_data.cc#L265-L291)). So `contains()` most likely stays `true` and no `onRemoved` fires. **UNVERIFIED** (source reading only).
- **Static content scripts on a withheld site** are not injected. They are recorded as "blocked actions", and Chrome's UI shows a reload bubble. A `document_start` script (`BLOCKED_ACTION_SCRIPT_AT_START`) needs a page refresh before it can run ([site_permissions_helper.cc#L34-L35](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions/site_permissions_helper.cc#L34-L35), [extension_action_runner.cc#L95-L107](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/extensions/extension_action_runner.cc#L95-L107)).

### Firefox MV3

- **MV3 host permissions are "origin controls".** `originControls` is `true` for every MV3 extension ([FF/toolkit/components/extensions/Extension.sys.mjs#L1995](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L1995)). With origin controls on, Firefox treats the manifest's `host_permissions` and content-script `matches` as optional origins (`manifestOptionalPermissions`, [Extension.sys.mjs#L1353-L1375](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L1353-L1375)), and `NO_PROMPT_PERMISSIONS` contains no origins ([#L1231](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L1231)).
- **They are granted at install.** Since Fx127, the install prompt shows the `host_permissions` and `content_scripts` hosts and Firefox grants them on install ([MDN host_permissions](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/host_permissions), [Extension Workshop MV3 migration](https://extensionworkshop.com/documentation/develop/manifest-v3-migration-guide/)). In source, pref `extensions.originControls.grantByDefault` = `true` ([FF/modules/libpref/init/all.js#L3121](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/modules/libpref/init/all.js#L3121)). At startup with reason `ADDON_INSTALL`, `ExtensionPermissions.add(manifest origins)` runs ([Extension.sys.mjs#L4401-L4425](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L4401-L4425)).
  - **No install-time opt-out.** The install prompt's only checkboxes are private browsing and the `technicalAndInteraction` data-collection checkbox ([FF/browser/modules/ExtensionsUI.sys.mjs#L281-L294, L596-L630](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/browser/modules/ExtensionsUI.sys.mjs#L281-L294)). The user can withhold host access only after install, using the controls below.
  - **Updates do not auto-grant new origins.** The grant block runs only for `ADDON_INSTALL` (or `ADDON_UPGRADE` when an enterprise policy requires the add-on). New host permissions in an update are not shown to the user (MDN, bug 1893232) and are not granted. The extension must request them.
- **User revocation in about:addons.** The Permissions tab lists optional permissions, including MV3 manifest origins and any granted extra origins, as `moz-toggle`s ([addon-permissions-list.mjs#L65-L80, L166-L221](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/mozapps/extensions/content/components/addon-permissions-list.mjs#L65-L80)). The all-sites toggle uses the text "Access your data for all websites". Turning it off removes every "all sites" pattern declared in the manifest, and only those patterns (`normalizeOptional`, [ExtensionPermissions.sys.mjs#L374-L402](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L374-L402)).
- **Per-site control in the unified extensions panel.**
  - While the extension holds all-sites access, the state is `{allDomains, hasAccess}` and the menu offers only "On All Sites". `setWhenClicked` cannot revoke an all-sites pattern ("all urls wouldn't be currently be revoked") ([ExtensionPermissions.sys.mjs#L721-L723, L826-L879](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L721-L723), [ExtensionsUI.sys.mjs#L833-L868](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/browser/modules/ExtensionsUI.sys.mjs#L833-L868)).
  - Once all-sites access is revoked, the menu offers "Only When Clicked" and "Always Allow on {domain}". "Always Allow" grants `*://host/*` ([originControls.ftl](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/browser/locales/en-US/browser/originControls.ftl), `setAlwaysOn` [#L771-L823](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L771-L823)).
  - Conclusion: with all-sites granted, I found no per-site block in Firefox.
- **`permissions.contains({origins})`** checks `allowedOrigins.subsumes`. **`getAll()`** returns `activePermissions` ([FF/…/parent/ext-permissions.js#L221-L253](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/parent/ext-permissions.js#L221-L253)). Both reflect the withheld state.
- **Events.** about:addons toggles and panel choices go through `ExtensionPermissions.add/remove`, which emit `change-permissions`. That maps to `permissions.onAdded` / `onRemoved` ([ExtensionPermissions.sys.mjs#L431-L545](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L431-L545), [ext-permissions.js#L49-L99](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/parent/ext-permissions.js#L49-L99)).
- **Static content scripts** in MV3 always check `CanAccessURI` at match time ("Origin permissions are optional in mv3, so always check them at runtime"). They do not run on a withheld site ([FF/toolkit/components/extensions/WebExtensionPolicy.cpp#L904-L907, L1063-L1067](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/WebExtensionPolicy.cpp#L904-L907)).

## 2. `permissions.request` / `remove` for a sub-origin when `host_permissions` has `*://*/*` or `<all_urls>`

### Chrome

`UnpackPermissionSet` checks required hosts **first**. Any requested origin that a required pattern contains is classified as `required_explicit_hosts`, even if the same origin is also listed in `optional_host_permissions` ([permissions_api_helpers.cc#L200-L226](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api_helpers.cc#L200-L226)).

- **(a) Granted:** the origin is already active, so `total_new_permissions` is empty and the call resolves `true` with no prompt ([permissions_api.cc#L397-L401](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api.cc#L397-L401)). Like every `request()`, it needs a user gesture (`kUserGestureRequiredError`, #L318-L321).
- **(b) Withheld:** the request is allowed. Withheld required hosts become `requested_withheld_` ([#L371-L395](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api.cc#L371-L395)), and a host has a warning, so the user sees a prompt. The docs say: "These permissions must either be defined in the `optional_permissions` field of the manifest or be required permissions that were withheld by the user" ([permissions API](https://developer.chrome.com/docs/extensions/reference/api/permissions)). No `optional_host_permissions` entry is needed.
- **(c) Remove:** any origin that a required pattern covers fails with **"You cannot remove required permissions."** ([#L46-L47, L233-L245](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/api/permissions/permissions_api.cc#L233-L245)). The source comment adds: "This won't support removal of required permissions that can withheld."
- **(d) Persistence:** narrowing to On click or On site revokes every revokable host grant, including one obtained through `request()` while access was withheld (§1). After a user narrows, broadens and narrows again, the specific grant is gone. If the request happened while all-sites access was active, it resolved `true` without recording anything (a). **UNVERIFIED** at runtime; this is from source reading.
- **Consequence of the classification:** with `<all_urls>` or `*://*/*` in `host_permissions`, an entry in `optional_host_permissions` that those patterns cover is treated as required for request, remove and contains.

### Firefox MV3

- **(a) Granted:** with `extensions.webextOptionalPermissionPrompts` = `true` (default, [FF/browser/app/profile/firefox.js#L34](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/browser/app/profile/firefox.js#L34)), origins that `allowedOrigins` already subsumes are filtered out. The call returns `true` without prompting and **without storing** the specific origin ([ext-permissions.js#L167-L187](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/parent/ext-permissions.js#L167-L187)).
- **(b) Withheld:** the request is allowed when `optionalOrigins` subsumes the origin. Manifest `host_permissions` count as optional origins under origin controls ([#L129-L136](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/parent/ext-permissions.js#L129-L136), [Extension.sys.mjs#L4585-L4594](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L4585-L4594)). No `optional_host_permissions` entry is needed. Prompt header: "{extension} requests additional permissions" ([extensions.ftl#L15](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/locales/en-US/toolkit/global/extensions.ftl#L15)). On accept, the origin is stored as its own entry.
- **(c) Remove:** nothing blocks it outside enterprise policy ("You cannot remove required permissions" is thrown only when `isAddonRequiredByPolicy`, [#L255-L275](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/parent/ext-permissions.js#L255-L275)). `ExtensionPermissions.remove` deletes only stored patterns that exactly match after normalization ([ExtensionPermissions.sys.mjs#L492-L545](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L492-L545)). Removing `https://dav.example.com/*` while only `<all_urls>` is stored does nothing and resolves `true`.
- **(d) Persistence:** an origin granted separately while all-sites access was off survives the all-sites toggle going on and off, because that toggle only touches all-sites patterns. about:addons shows it as its own toggle. An origin "requested" while all-sites access was on was never stored (a), so it disappears with all-sites access.

## 3. `activeTab`

- **Chrome:** "Executing an action" grants activeTab. Opening the popup is the action. The grant gives the tab's URL, title and favicon, plus `scripting.executeScript` / `insertCSS` on that tab when `scripting` is declared. Install warning: none ([activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [permissions list](https://developer.chrome.com/docs/extensions/reference/permissions-list)). In source, `GrantIfRequested` grants tab-scoped host access when the extension has `activeTab` **or** when the extension's *withheld* hosts match the URL: "even if it doesn't have the activeTab permission in the manifest" ([CR/extensions/browser/permissions/active_tab_permission_granter.cc#L135-L179](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/browser/permissions/active_tab_permission_granter.cc#L135-L179)). `RunAction(grant_tab_permissions)` calls it for action clicks, popup included ([extension_action_runner.cc#L95-L143](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/extensions/extension_action_runner.cc#L95-L143)). If the site has blocked actions, the click runs them instead.
- **Firefox:** MDN lists the triggers as the toolbar button or page action, a context menu item, a keyboard shortcut (Fx63+), a button on an extension page, and an omnibox suggestion (Fx142+) ([MDN permissions](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/permissions)). In source, opening the popup calls `setActiveTabForPreload(tab)` and then `addActiveTabPermission` ([FF/browser/components/extensions/parent/ext-browserAction.js#L621-L626](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/browser/components/extensions/parent/ext-browserAction.js#L621-L626), [ExtensionActions.sys.mjs#L215-L226](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionActions.sys.mjs#L215-L226)). The grant gives `Tab.url`, `title` and `favIconUrl`, plus script injection on the top-level page and same-origin frames (MDN, MV3 note). `activeTab` has no prompt string: it is not in `PERMISSIONS_WITH_MESSAGE` ([ExtensionPermissionMessages.sys.mjs#L32-L59](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissionMessages.sys.mjs#L32-L59)). In MV3 the origin-controls state "whenClicked" depends on `activeTab` ([ExtensionPermissions.sys.mjs#L679-L720](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPermissions.sys.mjs#L679-L720)).
- **Runtime check of `tabs.query` → `url` with host access withheld:** I did not test this in a running browser. The two points above are from source and docs.

## 4. Content scripts after install, update or permission grant

- **Chrome: not injected into tabs that were already open.** When scripts are updated, the renderer's `ScriptInjectionManager::OnUserScriptsUpdated` only drops pending injections. Injection is driven by the frame lifecycle (document start, end, idle) ([CR/extensions/renderer/script_injection_manager.cc#L288-L295](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/renderer/script_injection_manager.cc#L288-L295)). I found no developer.chrome.com sentence that states this directly (**UNVERIFIED in docs**). Prior art treats it as fact (below).
- **Chrome: orphaned scripts.** After an update or reload, the old content script's extension API calls throw `"Extension context invalidated."` ([CR/extensions/renderer/bindings/api_binding_util.cc#L109-L116](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/renderer/bindings/api_binding_util.cc#L109-L116)). Ports disconnect. The old script's DOM (injected elements) stays in the page.
- **Firefox: injects into existing tabs on extension startup.** This covers install, update and enable. `ExtensionProcessScript.initExtension` calls `policy.injectContentScripts()`, which walks every content browsing context and runs the matching scripts ([FF/…/ExtensionProcessScript.sys.mjs#L219-L225](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionProcessScript.sys.mjs#L219-L225), [ExtensionPolicyService.cpp#L404-L430](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionPolicyService.cpp#L404-L430)). On shutdown, old content-script sandboxes are nuked (`Cu.nukeSandbox`) and their CSS is removed ([ExtensionContent.sys.mjs#L1195-L1213, L1304-L1311](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionContent.sys.mjs#L1195-L1213)).
- **Firefox: on a host-permission grant** (`Extension:UpdatePermissions`), only the policy's allowed origins are updated. I found no injection into already-loaded pages ([ExtensionProcessScript.sys.mjs#L348-L372](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/ExtensionProcessScript.sys.mjs#L348-L372)). **UNVERIFIED** at runtime.
- **Prior art:**
  - Proton Pass re-injects `orchestrator.js` into all `http(s)` tabs on `install`/`update`, **Chrome build only**. The comment reads "Re-inject content-scripts to avoid stale extension contexts only on Chrome as Firefox handles content-script re-injection" ([PP/applications/pass-extension/src/app/worker/services/activation.ts#L105-L137](https://github.com/ProtonMail/WebClients/blob/46dfd76cb94f637c4fa7847667ebfa2a81bd5728/applications/pass-extension/src/app/worker/services/activation.ts#L105-L137), [injection.ts#L62-L73](https://github.com/ProtonMail/WebClients/blob/46dfd76cb94f637c4fa7847667ebfa2a81bd5728/applications/pass-extension/src/app/worker/services/injection.ts#L62-L73)).
  - Bitwarden calls `loadAutofillScriptsOnInstall()` → `injectAutofillScriptsInAllTabs()` (every `http*` tab, every frame) from `checkOnInstalled`. `reloadAutofillScripts()` retires old frames first ([BW/apps/browser/src/background/runtime.background.ts#L554-L556](https://github.com/bitwarden/clients/blob/2508d0dcf3b57657e9ef525b20bdf117d5338f7a/apps/browser/src/background/runtime.background.ts#L554-L556), [autofill.service.ts#L208-L239, L3179-L3190](https://github.com/bitwarden/clients/blob/2508d0dcf3b57657e9ef525b20bdf117d5338f7a/apps/browser/src/autofill/services/autofill.service.ts#L208-L239)).
  - KeePassXC-Browser only opens a getting-started tab on `install` ([KP/keepassxc-browser/background/init.js#L82-L88](https://github.com/keepassxreboot/keepassxc-browser/blob/8b0b2c4347126f4983f59ea7dd6ca2a2a667cf48/keepassxc-browser/background/init.js#L82-L88)).

## 5. Install warnings and optional-capability

### Host patterns

- **Chrome:** `<all_urls>`, `*://*/*` and `http://*/*`+`https://*/*` all trigger `kHostsAll`. - **Firefox:** `<all_urls>`, and any pattern whose host is `*` (so `*://*/*` and `http(s)://*/*` too), show **"Access your data for all websites"** ([Extension.sys.mjs#L2636-L2690](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L2636-L2690), [extensions.ftl#L70](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/locales/en-US/toolkit/global/extensions.ftl#L70)).

## 6. Clipboard

- **Chrome, popup on click:** no permission is needed. `AllowWriteToClipboard()` returns `true` for any `kPrivilegedExtension` context that is not a service worker ("All blessed extension pages could historically write to the clipboard"). Other contexts need `clipboardWrite` ([CR/chrome/renderer/chrome_content_settings_agent_delegate.cc#L122-L141](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/renderer/chrome_content_settings_agent_delegate.cc#L122-L141)).
- **Chrome, clearing later with no page open:**
  - Offscreen documents have context type `kOffscreenExtension` ([context_type.mojom](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/extensions/common/mojom/context_type.mojom)), not `kPrivilegedExtension`. They therefore need `clipboardWrite` to write. Google's sample uses `reasons: [CLIPBOARD]`, `document.execCommand('copy')` (because "`navigator.clipboard` requires that the window is focused, but offscreen documents cannot be focused") and `"permissions": ["offscreen", "clipboardWrite"]` ([cookbook.offscreen-clipboard-write](https://github.com/GoogleChrome/chrome-extensions-samples/tree/main/functional-samples/cookbook.offscreen-clipboard-write)).
  - The Clipboard API in extension service workers exists behind `ClipboardOnExtensionServiceWorker`, which is `FEATURE_DISABLED_BY_DEFAULT` ([CR/third_party/blink/common/features.cc#L112-L113](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/third_party/blink/common/features.cc#L112-L113), [clipboard.idl](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/third_party/blink/renderer/modules/clipboard/clipboard.idl)). It is not available in stable by default.
- **Reading the clipboard** (to clear only if it still holds our value) needs `clipboardRead` in Chrome (`AllowReadFromClipboard`, same file #L105-L120).
- **Firefox:** `clipboardWrite` is not needed for writes inside a short-lived user-event handler. It is needed outside one, including from background pages via `navigator.clipboard.writeText()` or `execCommand`. Reading needs `clipboardRead`; without it, extensions get a paste prompt (Fx147+) ([MDN Interact with the clipboard](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Interact_with_the_clipboard)).
- **Prior art:**
  - **Bitwarden** (MV3 Chrome: `clipboardRead` + `clipboardWrite` + `offscreen`, all required). It uses an offscreen `CLIPBOARD` document when there is no DOM ([browser-platform-utils.service.ts#L262-L270, L361-L381](https://github.com/bitwarden/clients/blob/2508d0dcf3b57657e9ef525b20bdf117d5338f7a/apps/browser/src/platform/services/platform-utils/browser-platform-utils.service.ts#L262-L270)). Its clear timer reads the clipboard and writes `""` only `if (clipboardValue === clipboardValueNow)` ([BW/libs/common/src/platform/services/system.service.ts#L48-L53](https://github.com/bitwarden/clients/blob/2508d0dcf3b57657e9ef525b20bdf117d5338f7a/libs/common/src/platform/services/system.service.ts#L48-L53)).
  - **Proton Pass** (`clipboardRead` + `clipboardWrite` **optional**, requested together; `offscreen` required on Chrome). It tries `navigator.clipboard` first and falls back to an offscreen document on Chrome. The offscreen justification is "being able to clear clipboard after a delay". The clear alarm compares before clearing: `if (current === clipboardValue) clipboard.write('')`. A `permissions.onAdded` listener finishes the copy when the popup closed during the prompt ([clipboard.ts#L26-L133](https://github.com/ProtonMail/WebClients/blob/46dfd76cb94f637c4fa7847667ebfa2a81bd5728/applications/pass-extension/src/app/worker/services/clipboard.ts#L26-L133), [offscreen.utils.ts#L8-L14](https://github.com/ProtonMail/WebClients/blob/46dfd76cb94f637c4fa7847667ebfa2a81bd5728/applications/pass-extension/src/app/worker/offscreen/offscreen.utils.ts#L8-L14), [packages/pass/lib/clipboard/service.ts#L14-L18](https://github.com/ProtonMail/WebClients/blob/46dfd76cb94f637c4fa7847667ebfa2a81bd5728/packages/pass/lib/clipboard/service.ts#L14-L18)).
  - **KeePassXC-Browser** declares `clipboardWrite` and uses it only in the options page (`navigator.clipboard.writeText`). The extension has no clipboard-clearing code ([options.js#L343](https://github.com/keepassxreboot/keepassxc-browser/blob/8b0b2c4347126f4983f59ea7dd6ca2a2a667cf48/keepassxc-browser/options/options.js#L343)). The desktop app handles copying, so whether it clears is outside the extension. **UNVERIFIED**.
  - **1Password** Chrome MV3 declares neither clipboard permission nor `offscreen`, so how it clears is **UNVERIFIED** (closed source).

## 8. Storage eviction and quota

- **Chrome:**
  - `ExtensionSpecialStoragePolicy::IsStorageProtected` returns `true` for every `chrome-extension:` origin. `IsStorageUnlimited` is `true` for extensions with `unlimitedStorage` ([CR/chrome/browser/extensions/extension_special_storage_policy.cc#L123-L159](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/extensions/extension_special_storage_policy.cc#L123-L159)).
  - Quota eviction considers only `persistent = 0` buckets. It skips the default bucket when the origin is `IsStoragePersistent` **or** `IsStorageUnlimited` ([CR/storage/browser/quota/quota_database.cc#L626-L680](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/storage/browser/quota/quota_database.cc#L626-L680)). So: without `unlimitedStorage`, extension IndexedDB is best-effort and evictable. With it, the default bucket is excluded from eviction and quota is unlimited. The permissions list says `unlimitedStorage` gives "an unlimited quota for `chrome.storage.local`, `IndexedDB`, `Cache Storage`, and `Origin Private File System`".
  - `navigator.storage.persist()` uses heuristics (installed app domain, important or engaged sites) ([persistent_storage_permission_context.cc#L49-L140](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/storage/persistent_storage_permission_context.cc#L49-L140)). There is no extension-specific branch, so the result in extension pages is **UNVERIFIED**.
  - Docs say Web Storage data "is lost when the user clears their browsing history". `chrome.storage` data persists ([storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)). Whether "clear browsing data" removes extension-origin IndexedDB, given `IsStorageProtected`, is **UNVERIFIED**.
  - `storage.local` quota: **10 MB** (5 MB in Chrome ≤113). Unlimited with `unlimitedStorage`.
- **Firefox:**
  - `unlimitedStorage` makes Firefox add the site permissions `WebExtensions-unlimitedStorage` **and `persistent-storage` = ALLOW** for the extension principal ([FF/…/Extension.sys.mjs#L4054-L4090](https://github.com/mozilla-firefox/firefox/blob/098e537cc4338b343383540dd7e7907fece986b7/toolkit/components/extensions/Extension.sys.mjs#L4054-L4090)). The storage is then persistent, and MDN says it can be created "without the browser prompting".
  - Without `unlimitedStorage`, storage is best-effort under the IndexedDB limits: 10% of disk or 10 GiB group limit, LRU eviction ([MDN quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)). `persist()` in Firefox normally shows a prompt; the behaviour for a moz-extension page without `unlimitedStorage` is **UNVERIFIED**.
  - `storage.local` is subject to the same IndexedDB limits. It needs `unlimitedStorage` to exceed them and can still hit the global limit ([MDN storage.local](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/local)).

## 10. Firefox export: `downloads.download({saveAs:true})` vs `<a download>`

## 13. Chrome Local Network Access (LNA)

- **Status:** the LNA permission prompt shipped in **Chrome 142** (opt-in testing from 138). It covers `fetch()`, subresources and subframes to private, link-local and loopback addresses. "Local network requests from Service Workers and Shared Workers require that the worker's origin has previously been granted the Local Network Access permission" ([LNA blog](https://developer.chrome.com/blog/local-network-access)). The blog does not mention extensions.
- **Extensions in source:** `ChromeContentBrowserClient::DetermineAddressSpaceFromURL` returns `kLoopback` for the `chrome-extension` scheme ([CR/chrome/browser/chrome_content_browser_client.cc#L2281-L2295](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/chrome_content_browser_client.cc#L2281-L2295)). A browser test asserts "the chrome-extension:// scheme is considered local for the purpose of Local Network Access" ([local_network_access_browsertest.cc#L319-L370](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/chrome/browser/local_network_access/local_network_access_browsertest.cc#L319-L370)). A request from a loopback-space initiator to a private IP is not a "less private → more private" request, so LNA would not prompt. No new extension permission exists for this.
- **Service workers:** they compute their address space with the same helper (`CalculateIPAddressSpace`, used from [service_worker_context_wrapper.cc](https://github.com/chromium/chromium/blob/4984bf7a73a4ebec173430f474c5d005a9fe041d/content/browser/service_worker/service_worker_context_wrapper.cc)). The browser test exercises an extension *page*, not an extension service worker. **UNVERIFIED** at runtime for an extension service worker fetching a private-IP HTTPS WebDAV server.

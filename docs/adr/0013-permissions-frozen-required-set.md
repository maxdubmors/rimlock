# Permissions: a frozen required set, and anything with a warning beyond site access is optional

Chrome disables an Extension when an update adds a required permission that carries an install warning, and Firefox holds such an update back. Firefox also never grants host access that an update adds. So the required set ships complete in the first release and does not grow. It holds what every user needs from the first run: host access to `http://*/*` and `https://*/*` (the only warning) plus `storage`, `unlimitedStorage`, `idle`, `alarms`, `scripting`, `activeTab` and, in Chrome, `offscreen`, none of which shows a warning. Every other permission that carries a warning belongs to a feature some users never touch. It is declared optional and requested inside the click that needs it: `clipboardRead` + `clipboardWrite` at the first Copy (for clearing only if the clipboard still holds our value), `privacy` from "Turn off the browser's password saving", `downloads` at the first Export… in Firefox, and `nativeMessaging` later (ADR-0011). A refusal disables only that feature. The host pattern is `http(s)` rather than `<all_urls>`: the warning is the same, and `file://`, `ftp://` and other schemes are never filled. The Extension never declares `tabs`, `webRequest`, `webNavigation`, `background` or `notifications`, and it declares no `optional_host_permissions`.

## Considered Options

- **Everything required** (Bitwarden). Rejected: an extra install warning for clipboard clearing, and any later addition with a warning disables the Extension in Chrome.
- **Everything optional except site access.** Rejected: permissions without a warning gain nothing from a prompt, and `unlimitedStorage` cannot be optional in either browser.
- **`<all_urls>`.** Rejected: the same warning for schemes that are never filled.
- **WebDAV origins in `optional_host_permissions`.** Rejected: Chrome treats any origin covered by `host_permissions` as required anyway.

## Consequences

- **Site access can be withdrawn** in both browsers after install, globally or per site (Firefox has no install-time opt-out). The popup uses `activeTab` to show the Matches for the current tab and to Fill through a one-off injection. A banner offers **Allow on this site** / **Allow on all sites**. The popup checks access with `permissions.contains` and with a ping to the content script, because Chrome's per-site "block all extensions" may not show up in `contains`.
- **Re-injection:** Chrome does not run declared content scripts in tabs that were open before an install or update, so `onInstalled` injects into every `http(s)` tab and frame. Both browsers inject again after `permissions.onAdded`. Orphaned content scripts detect the lost connection and remove their UI.
- **WebDAV:** Connect still calls `permissions.request` for the server origin (no prompt when site access is granted, a prompt for that origin alone when it is withheld). Every Sync checks `permissions.contains` and shows **Grant** when access is missing (ADR-0008). Removing a WebDAV Database does not call `permissions.remove`, because Chrome refuses to remove a required origin.
- **`unlimitedStorage`** is required because without it extension IndexedDB is best-effort in both browsers and could be evicted along with the Local copy and its Pending changes.
- **One offscreen document** in Chrome, created on first need with reasons `[BLOBS, CLIPBOARD]`. No reason covers holding a file handle, and the reasons of a document cannot change after it is created. It lives until the browser closes, because closing it would drop the file grant (ADR-0007). Firefox has no offscreen API; clipboard clearing runs in the event page.
- **Content scripts** declare `all_frames: true` and no `match_about_blank` / `match_origin_as_fallback`. `web_accessible_resources` exposes only the iframe HTML for the Inline menu and Save prompt, to `http(s)` pages, with `use_dynamic_url: true` in Chrome.
- **Store disclosures:** Chrome Web Store discloses Authentication information and Website content. AMO declares `data_collection_permissions: ["none"]`, with a reviewer note that the only network traffic is the encrypted `.kdbx` going to a WebDAV server the user configures. The privacy policy is `PRIVACY.md` in the repository.
